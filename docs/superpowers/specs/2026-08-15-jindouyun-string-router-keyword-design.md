# 筋斗云-字符串关键词路由设计

## 目标

把现有的完整 LoRA 名称精确绑定改为用户自定义关键词路由。节点接收“筋斗云随机LORA”的 `LoRA` 名称后，在名称中查找用户填写的字面关键词，并输出命中方案的拼接文本。

方案名称与最近记录的 LoRA 名称保持一致，减少方案选择器、运行状态与实际输入名称之间的识别差异。

## 匹配规则

- 每个方案可填写一个或多个关键词，每行一个。
- 匹配采用不区分英文大小写的字面包含判断。例如关键词 `V1.1` 可命中 `DSMQIAOXING-K9E-8-V1.1_4000_loss-0.11724`，关键词 `V1.0` 不会命中该名称。
- 不进行模糊匹配、相似度匹配、词干转换、触发词推断或提示词内容搜索。
- LoRA 输入只移除支持的模型文件后缀，并统一路径分隔符；名称中的标点、数字和版本号保持不变。
- 若同一个 LoRA 名称命中多个方案，按方案列表从上到下选择第一个，并在运行状态中显示冲突提示。
- 没有关键词命中时继续使用默认方案；未设置默认方案时输出空字符串。

## 方案名称同步

- “绑定当前 LoRA”按钮改名为“记录当前 LoRA”。
- 点击后把最近一次运行收到的完整 LoRA 名称写入当前方案名称。
- 点击后不自动把完整 LoRA 名称写入关键词；关键词由用户根据版本号或其他可区分部分手工填写。
- 用户仍可随时手工修改方案名称，不影响关键词匹配。
- 方案选择器直接显示方案名称，因此记录后会显示与当前 LoRA 输入一致的名称。

## 编辑器

- 原“精确绑定的 LoRA”改为“匹配关键词”。
- 输入框提示改为“每行一个关键词，例如 V1.1”。
- 关键词可以包含中文、英文、数字、空格和标点，按字面内容匹配。
- 同一个完全相同的关键词只允许属于一个方案；在新方案中填写时从旧方案移除。
- 现有工作流配置继续沿用 `bindings` 字段，字段中的旧完整 LoRA 名称自动作为长关键词使用，无需迁移。

## 运行反馈

- 单一命中显示绿色：`已匹配：方案名称`，并显示命中的关键词和实际 LoRA 名称。
- 未命中但使用默认方案显示蓝色。
- 未命中且无默认方案显示粉色。
- 多方案命中显示橙色冲突状态，同时仍按方案顺序输出第一个方案，避免工作流中断。

## 测试

- 覆盖 `V1.1` 与 `V1.0` 的独立匹配，以及大小写差异。
- 验证不进行模糊、前缀、相似度和提示词内容匹配。
- 覆盖多关键词共享方案、重复关键词归属、默认方案和多方案冲突顺序。
- 验证记录当前 LoRA 后方案名称同步，但关键词不会被自动覆盖。
- 验证旧完整名称绑定配置仍能正常匹配。
